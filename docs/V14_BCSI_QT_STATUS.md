# v14 工程改动与验证记录（BCSI 实验分支）

## 本次已落地的代码

### RX 队列过载保护

- `internal/rx/manager.go`：`Submit` 不再等待队列空位；队列满时拒绝最新到达的包，保持已入队 FIFO 顺序，并通过原子计数器累计 `DroppedPackets()`。关闭状态使用 `atomic.Bool`，提交路径不再竞争 Manager 的 session 大锁。
- `internal/rx/manager_test.go`：增加/更新饱和测试，阻塞消费者回调后快速灌入 544 个包，确认 Submit 在 250 ms 内返回、512 个排队包保留、32 个新包被计数丢弃；完整 RX 包管理器竞态检测通过。

### 独立 BCSI 编码器

新增 `internal/image/bcsi/`，不改 SSDV、PCSI-MMT 或现有 transport/profile 的协议定义。

- 8×8 空间独立块，Y/Cb/Cr 三分量测量。
- 采用 seeded 2-D low-sequency partial Walsh-Hadamard 测量算子；相同二维序列等级内按种子打乱，优先保留 DC 和粗尺度空间信息。
- Haar 2-D 小波作为稀疏重建域，接收端使用迭代阈值收缩恢复。
- 依据块亮度方差自适应调整 Y 测量预算，色度测量数约为亮度一半。
- 标量量化、差分 signed-varint 编码；较长块载荷才尝试 DEFLATE，并只在确实缩短时采用。DEFLATE workspace 通过 `sync.Pool` 复用。
- 每块独立携带图像尺寸、块索引、测量数、量化步长、种子、压缩标志和 CRC32；解码不依赖前序块，可乱序接收、去重和校验损坏包。
- 接收端支持有界 worker pool（最多 16 个 worker）、Context 取消、已解码块缓存和渐进预览。缺块使用最近已恢复块进行空间隐藏；这只能改善画布连续性，不会重建丢失细节。

### 图像质量与基准工具

- `internal/imagequality/metrics.go`：增加 RGB PSNR 和 8×8 窗口亮度 SSIM。
- `internal/image/bcsi/wavelet.go`：增加轻量 Haar + 标量量化 + DEFLATE 参考编码器，仅作小波基准，不宣称是 JPEG 2000。
- `cmd/bcsi-benchmark/`：可重复生成 320×240、448×336、640×480 的 25%、37.5%、50% 亮度基准采样测试，并比较 Go 标准 JPEG Q75、按字节目标选择质量的 JPEG、Haar 参考方案；报告包括 PSNR、SSIM、实际字节数、编码/解码耗时、Go 分配量、理想 1200/2400 bit/s 载荷时长和 10/25/40% 随机块包丢失结果。
- 完整结果见 `docs/BCSI_BENCHMARK_REPORT.md`。

## 基准结果摘要

测试环境：Linux amd64，Go 1.23.2（测试时临时将 `go.mod` 中的 1.26.0 指令下调至 1.23.0，完成测试后已恢复为 1.26.0），可见 CPU 3 个；24 次重建迭代、3 个 worker。输入是固定合成 RGB 图（梯度、几何边缘和纹理），不是照片数据集。

| 分辨率 | 亮度采样率 | BCSI 数据量 | PSNR | SSIM | 编码时间 | 解码时间 |
|---|---:|---:|---:|---:|---:|---:|
| 320×240 | 25% | 79,203 B | 18.52 dB | 0.8866 | 7.3 ms | 170.3 ms |
| 320×240 | 37.5% | 97,178 B | 20.15 dB | 0.9344 | 8.1 ms | 154.1 ms |
| 320×240 | 50% | 114,834 B | 21.31 dB | 0.9558 | 11.8 ms | 143.4 ms |
| 448×336 | 25% | 155,288 B | 18.51 dB | 0.8852 | 15.1 ms | 285.5 ms |
| 448×336 | 37.5% | 190,468 B | 20.02 dB | 0.9290 | 18.4 ms | 318.4 ms |
| 448×336 | 50% | 224,913 B | 21.14 dB | 0.9510 | 22.9 ms | 289.4 ms |
| 640×480 | 25% | 317,714 B | 18.39 dB | 0.8891 | 23.6 ms | 614.2 ms |
| 640×480 | 37.5% | 390,057 B | 19.84 dB | 0.9310 | 31.5 ms | 653.4 ms |
| 640×480 | 50% | 460,225 B | 20.96 dB | 0.9529 | 48.2 ms | 644.0 ms |

**结果解读：** 该轮二维测量矩阵比初版一维/随机列方案显著改善；但在低采样档位仍略低于质量调到目标字节数的 JPEG。高档 BCSI 接近/略高于标准 JPEG 目标质量行，但该 JPEG 编码器在 Q100 已到质量上限、字节数未达到 BCSI 目标，因此不能把这一项解释为完全同码率优势。Haar 参考方案在本合成图上表现非常高，但它发送所有变换系数，不是压缩感知方法，且不能代表真实遥感/卫星图像。详见完整表格和实际字节差。

以 320×240、37.5% 亮度基准率为例，随机丢失 10/25/40% 块包后，独立重建块覆盖率为 90/75/60%，输出 PSNR 为 17.56/15.36/14.14 dB。缺失块由最近恢复块隐藏，图像不再是完整原始信息。

## 尚未完成 / 不能声称已验证的工作

1. **Qt 原生 UI 尚未迁移。** 当前版本仍是 Wails v2 + HTML/JS/CSS + WebView。本环境没有 Qt 6 Widgets 开发包、`qmake6` 或 `Qt6Widgets` pkg-config 项，因此无法编译和验证 MIQT Qt Widgets 应用。具体耦合点与迁移步骤见 `docs/PORT_QT6_WIDGETS.md`。目前不能声称已抛弃浏览器内核。
2. **BCSI 尚未接入无线电 TX/RX Profile。** 新编码器独立可调用，但目前没有新的 over-the-air profile、链路分包/重组配置或 UI 选择项；现有 SSDV/PCSI 路径保持不变。因而本报告的理想传输时间是裸 BCSI 包字节数除以 1200/2400 bit/s，不包含 CCSDS/AX.25、FEC、交织、调制和链路重传。
3. **跨平台构建未完成。** 算法包没有平台专用代码，但本轮只在 Linux amd64 执行测试；Windows/macOS 的 GUI、音频、串口、Qt 部署和释放构建尚未验证。
4. **图像数据集范围有限。** 当前 benchmark 使用确定性合成图；需要用实际卫星图像（自然场景、低照度、高噪声、文字/边缘图、彩色图）做样本集测试，再定默认采样率和量化策略。
5. **优化 JPEG 的边界。** 当前目标字节 JPEG 是使用 Go 标准 JPEG 编码器搜索质量档位，不是 libjpeg-turbo 优化 Huffman 表的独立实现；报告已明确该限制。

本分支适合作为“RX 队列过载修复 + BCSI 实验实现/基准工具”的中间版本，不应标记为 Qt 迁移完成版或可直接上线发射的 BCSI 版本。
