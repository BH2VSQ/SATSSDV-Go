# SATSSDV-Go v13 修复说明

日期：2026-11-04

本版本基于 v12 源码，修复循环发送倒计时取消、降低 RX/PCSI 内存峰值、调整模板预设界面，并在 TX 调制音频上增加不重采样的频带边缘滤波。

## 1. 循环发送倒计时取消

- TX scheduler 在倒计时阶段收到 context cancellation 时，明确发出 `cancelled` 事件。
- 前端 Stop TX 动作会立即调用 `restoreRepeatInterval()`；收到后端 `cancelled` 事件后也会恢复原始发送间隔。
- 新增 `TestRunCancellationDuringCountdownEmitsCancelled`，覆盖倒计时中途取消的后端行为。
- 前端结构测试增加回归检查，确保 Stop 动作和 `cancelled` 事件都恢复发送间隔。
- 补齐简体中文、英文和日文的 `tx.stopped` 状态文案。

## 2. RX/PCSI 内存与资源优化

- RX 图像包队列容量从 2048 降为 512，限制系统繁忙时堆积的包副本；队列仍采用背压，不会主动丢弃已进入队列的有效数据包。
- PCSI 活跃/保留图像会话上限为 6；不活跃会话超过 3 分钟后会被定期清理。SSDV 会话也执行过期清理。
- PCSI 的 Y、Cb、Cr 三个 OWL-QN/DCT 优化器改为顺序执行，不再同时保留三个全分辨率求解工作区，降低峰值内存。
- PCSI 首次重建不再从全零 DCT 系数开始，而是根据已接收样本均值设置正交 DCT 的 DC 系数初值。这样早期预览在较少迭代时也能恢复正确的主色调。
- PCSI 预览迭代预算设为 16，最终重建为 96；8 次迭代的测试图像会出现明显绿色偏色，已通过回归测试拒绝该设置。
- SSDV 继续使用持久预览画布，只解码新包附近的重同步区段，避免每收到一个包都重新解析全量历史包。
- Wails 启动时设置 Go heap 软限制 640 MiB、GC target 80。该设置只约束 Go runtime 管理的堆，不包含 WebView、GPU、音频驱动等原生内存，因此不代表整个进程 RSS 被硬限制在 640 MiB。

## 3. 模板、SSID 和按钮布局

- 导入/导出模板包按钮采用相同按钮类与尺寸，垂直排列，导出位于导入下方。
- 预设名称行上移；清空“支持添加、复制和管理最多 32 个独立预设”提示。
- 删除当前预设按钮采用 Flex 居中，文字位于按钮中心。
- AX.25 SSID 标签统一为 `AX.25 SSID`，不再带括号说明。

## 4. TX 音频边缘滤波

在调制器输出之后增加原位滤波，不进行重采样、不改变突发长度或数据载波定时：

- 200 Hz 二阶 Butterworth 高通，抑制低频/DC/音频链路隆隆声。
- 4.8 kHz 四阶 Butterworth 低通，采用两个 Butterworth biquad 级联，抑制高频边缘能量。
- 测试要求 1200、1600、2200、2400 Hz 载波幅度变化小于 0.2 dB；60 Hz 和 8 kHz 越界音调振幅均低于输入的 20%。
- 滤波在原始 `[]float32` 波形上原位完成，不再复制整段 TX 波形。

## 5. 测试结果

通过：

- 全量 `go test ./...`
- 全量 `go vet ./...`
- `node --check frontend/app.js`
- `node frontend/ui_structure.test.cjs`
- TX queue / DSP / PCSI / SSDV 模块 Race 测试
- RX 队列背压、会话去重/过期、SSDV 缺包预览等定向 Race 测试
- PCSI 320×240 红色早期预览回归，确保低覆盖率下不再显示绿色偏色
- 调制音频载波通带与上下边缘抑制测试

限制与未验证项：

- 完整 `go test -race ./internal/rx` 在当前执行环境超时；一项带固定 3 秒等待期限的 SSDV 图像回归在 Race 插桩后超时，但普通测试通过。不能将 RX 全套 Race 标记为通过。
- 当前容器只有 Go 1.23.2，无法下载 Go 1.26.0 toolchain。因此测试时临时将本地 `go.mod` 指令降低到 1.23，测试结束后已恢复仓库要求的 `go 1.26.0`。测试结果不代表已在 Go 1.26/Wails Windows 目标上构建。
- 未完成 Windows Wails 原生打包，也未进行真实电台/SDR 发射频谱仪测量。滤波器已通过合成载波幅度与边缘抑制回归，实际声卡/电台链路仍建议复测。
- 640 MiB 是 Go heap 软限制，不是对 Windows 任务管理器中整个进程内存的硬上限。若系统占用仍高，需要分别测量 WebView、音频驱动、图像缓冲和 Go heap。
